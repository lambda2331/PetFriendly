The product premise

A nearby place is only part of the decision. Who could join? Is the place suitable for a pet? Who could help when plans change?

PetFriendly explores these questions in one neighborhood-based community: places to discover, people and groups to meet, walking requests and the conversations that connect them.

The starting market is Minsk, Belarus. The interface shown here is adapted into English for this portfolio. The product premise is a design hypothesis; this case study does not claim validated demand or measured user outcomes.

Where design meets implementation.

The useful part of the project is the reasoning between a screen and its behavior.

A system that travels from pixels to widgets.

Studio pairs Manrope headings with Golos Text, quiet neutral surfaces and a lime accent reserved for primary actions and selected navigation.

Semantic color roles support light, dark and system themes. The Flutter implementation bundles the fonts and maps the visual language into a shared theme and reusable UI components.

Location helps discovery.
It does not define identity.

A person’s public profile exposes a district rather than exact coordinates. Manual city selection stays under the user’s control, and place browsing remains available when location permission or a map token is missing.

The native map uses Mapbox; catalog entries retain OpenStreetMap provenance. Missing pet-access evidence is represented as unknown, so a map pin never becomes an unsupported promise.

Trust needs rules behind the interface.

Walking help is more than an “Offer to help” button. The native flow separates a request, responses, assignment and completion, with server-side checks for privileged changes.

Helper reviews belong to completed agreements. Chat access depends on membership. These constraints connect interface states to authorization rather than leaving trust to presentation alone.
