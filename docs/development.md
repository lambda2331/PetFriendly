# Локальная разработка

Flutter 3.47.6 / Dart 3.13.5 установлен в `~/.cache/petfriendly/flutter`. Зависимости зафиксированы. Приложение поддерживает демо-режим и локальный Supabase; это альфа для синтетических данных. Статус этапов — в [progress.md](progress.md).

## Запуск приложения

```sh
./scripts/run-ios.sh
PETFRIENDLY_CONFIG=config/supabase.local.json ./scripts/run-ios.sh
```

Первый вариант — демо; второй — локальная авторизация и серверные данные. Скрипт поддерживает PETFRIENDLY_FLUTTER_BIN и PETFRIENDLY_SIMULATOR_ID. Для Android SDK установлен в `~/.cache/petfriendly/android-sdk`, AVD называется petfriendly_dev. Android использует адрес хоста `10.0.2.2`, iOS Simulator — `127.0.0.1`.

```sh
export ANDROID_HOME="$HOME/.cache/petfriendly/android-sdk"
"$HOME/.cache/petfriendly/flutter/bin/flutter" run -d emulator-5554 --dart-define-from-file=config/test-android.local.json
```

Сборка Android использует Java 17, AGP 8.11.1, Kotlin 2.2.20, Gradle 8.14.3 для совместимости Mapbox. iOS использует CocoaPods и deployment target 15. SwiftPM отключён только для этого проекта. Для реального iPhone нужны signing и capability push.

## Локальный сервер

На этом Mac сервер работает в отдельном Colima-профиле petfriendly; Docker Desktop и чужие контейнеры не менялись. CLI Supabase 2.120.0 установлен через tooling/package-lock.json.

```sh
npm ci --prefix tooling
colima start --profile petfriendly --cpu 2 --memory 4 --disk 32 --activate=false
export DOCKER_HOST="unix://$HOME/.colima/petfriendly/docker.sock"
./tooling/node_modules/.bin/supabase start --exclude studio,vector,logflare,imgproxy,supavisor
./tooling/node_modules/.bin/supabase functions serve --no-verify-jwt
```

API: localhost:54321, PostgreSQL:54322, тестовая почта Mailpit:54324. Edge Functions самостоятельно проверяют доступ; отключение шлюзовой проверки JWT нужно для современных publishable ключей. `supabase db reset` удаляет только данные этого локального проекта: используйте его осознанно. Миграции в supabase/migrations, импорт в supabase/seed.sql.

Конфигурации `config/*.local.json` исключены из Git. Скопируйте config/app.example.json в config/app.local.json. Клиенту разрешён только publishable/anon ключ; service_role и ключи провайдеров остаются на сервере. Приложение отказывается от server key и HTTP в release. Локальный HTTP разрешён только debug для loopback/Android host.

Пошаговая настройка и команды импорта: [services-setup.md](services-setup.md).

## Подключения сервисов

- Mapbox: заполнить MAPBOX_ACCESS_TOKEN публичным токеном с минимальными правами. Проверить бесплатную квоту и управление расходами в своём аккаунте до использования. Без токена работает список OSM, карта показывает отсутствие подключения. Текущий аккаунт — demo access без платёжного способа, с ограниченным Default public token в локальных файлах; Нативные тесты проверяют загрузку тайлов и OSM-маркеров в обеих темах; результаты в progress.md.
- Google/Apple: настроить провайдеры Supabase и разрешённый callback `petfriendly://auth/callback`; затем включить соответствующие AUTH_GOOGLE_ENABLED / AUTH_APPLE_ENABLED. Для релиза настроить подтверждённые HTTPS App/Universal Links. Custom scheme используется локальной альфой с PKCE.
- Telegram: создать серверный custom OIDC provider с идентификатором telegram, email_optional=true и минимальными scopes; проверить совместимость в staging; только после этого AUTH_TELEGRAM_ENABLED=true. Имена пользователя не служат идентификатором аккаунта.
- Firebase: указать четыре FIREBASE_* клиентских параметра из example отдельно для Android/iOS. Для iOS добавить APNs key в Firebase и capability. На сервере сохранить FIREBASE_SERVICE_ACCOUNT_JSON, развернуть dispatch-notifications и настроить защищённый планировщик его вызова. Очередь поддерживает lease/retry; push содержит только общую фразу, без текста чата. Настоящая доставка ещё не проверена.
- Для облачного Supabase применить миграции, импорт, развернуть обе функции, настроить подтверждение email и SMTP. Облачный проект пока не развёрнут.

## Реализованные сценарии

Пять вкладок, обе темы, локальные шрифты, движение с учётом accessibility. Профили/питомцы, группы/встречи, заявки и отклики, атомарное назначение помощника, подтверждение завершения владельцем, один отзыв после завершения. Сообщения читаются только участниками; retry использует nonce. Realtime передаёт идентификаторы уведомлений, сообщения загружаются после новой серверной проверки прав; есть периодическое обновление.

Email/password и подтверждение email, TOTP MFA, список/отзыв сессий, экспорт, удаление через Edge Function, жалобы/блокировка. Токены и PKCE — в Keychain/Keystore. Приватные чаты/адреса не кешируются на диске; app switcher на iOS прикрывается нейтральным экраном. Android использует FLAG_SECURE для блокировки снимков/recents и overlay для скрытого приложения; потеря фокуса нативной картой не перекрывает интерфейс. Избранные IDs, город и тема — локальные настройки.

OSM-каталог: 1828 мест Минска, 5 дублей объединены, исходные aliases сохранены в assets/data/minsk_places.json. Импорт `python3 scripts/import_osm.py`; источник/время и лицензия сохранены. Только 6 мест имеют явно заданный допуск собак; остальные не считаются автоматически pet-friendly. Google/Yandex не импортируются. Для других городов начальный каталог пуст.

## Полноэкранная карта и положение пользователя

В карточке карты кнопка «На весь экран» открывает отдельный экран без нижних вкладок, сохраняя центр/масштаб карты. Доступны перемещение, жесты масштаба, кнопки +/−, карточки по маркерам и закрытие. На этом экране загружается вся выбранная категория OSM; встроенная карта по-прежнему показывает первые 40 совпадений списка.

«Моё местоположение» запрашивает разрешение, отмечает положение синим и перемещает камеру. Дальнейшие обновления меняют точку, сохраняя возможность свободно двигать карту; повторное нажатие возвращает камеру к пользователю. Ручной город не заменяется. Обновления прекращаются при hidden/paused и при закрытии экрана, возобновляются при возвращении только после включения пользователем. Отказ/ошибка геолокации не мешают просматривать карту. GPS остаётся в памяти клиента, не сохраняется в аккаунте и не публикуется; фонового tracking нет. Карта использует Mapbox, системную геолокацию и их разрешения.

Unit/widget-проверки включают отказ в геолокации и отмену подписки при скрытии/закрытии экрана. Нативный тест дополнен полноэкранным открытием, жестом перемещения, кнопками масштаба и возвращением во встроенную карту.

В полноэкранном режиме близкие точки группируются по сетке Web Mercator с учётом масштаба. Число внутри группы — количество мест; нажатие приближает группу. При изменении камеры группировка обновляется с debounce. Данные места при объединении не теряются; положение пользователя исключено из группировки.

## Событие, карта и отдельный список — актуальная версия

«Рядом» сохраняет верхнюю шапку Studio, приветствие и карточку будущей встречи в выбранном городе над картой. На маленькой высоте/увеличенном тексте приветствие уступает место карточке и карте. Списка мест на основной странице нет. Выбор города и переходы к отдельному /places и полноэкранному режиму вынесены в строку над картой. Карта имеет горизонтальные отступы 24 px, нижний отступ 16 px и скругление 24 px. Жесты работают в обоих режимах, а кнопки масштаба/своей позиции и компас доступны только в полном. Список содержит поиск по названию/категории и четыре компактных Material select: категория, допуск из OSM, все/избранное и сортировка по имени/расстоянию. Фильтры общие с картой, остаются в памяти сессии; активность отмечена на кнопке списка. Расстояние — приблизительное по прямой, без Directions API; при отсутствии положения используется порядок по имени.

Одиночные места отмечаются категориями Material Icons (дерево/чашка/лапа/приборы), отрисованными в PNG локально и переданными native SDK. Числовые кластеры остаются. Геолокация останавливается при открытии списка, другой вкладки, скрытии приложения и закрытии карты. City geocoding использует системный geocoder, не импортирует каталог Google/Yandex. Старые HTML-макеты отражают предыдущую композицию; актуальный экран — Flutter.

Блок встречи использует ближайшее будущее, не отменённое событие из community repository для выбранного города. Нет событий — предложение открыть встречи/создать новую; загрузка и ошибка имеют отдельные состояния. Время карточки Минска выводится в UTC+3, а не в часовом поясе симулятора.


## Обновление личного кабинета и сообществ

Настройки открываются через шестерёнку на вкладке «Я» (/settings). Люди и сообщества разделены сегментами; /group/:id содержит участников, вступление, выход и чат. Приглашение создаёт черновик личного сообщения, а не добавляет человека автоматически. Demo repository повторно использует групповой чат при повторном вступлении. Авторы и created_at серверных сообщений отображаются в чате, для demo есть тестовые авторы и временные отметки.

image_picker используется только для локального просмотра фото. Ограничение 8 МБ, перекодирование PNG, данные в Riverpod-памяти; смена состояния авторизации очищает фото. Нет записи в preferences/Drift, загрузки в Storage или передачи фотографий другим пользователям. Создание сообщества сохраняет его данные как прежде, а фото остаётся временным предпросмотром. Кнопка выбора фото на странице сообщества доступна организатору. Фото профиля/питомца выбираются нажатием на изображение.


## Новые места и изоляция окружений

Миграция 202610080007 добавляет place_submissions, RPC submit_place и review_place_submission. Сервер проверяет категорию/координаты, ограничивает ожидающие заявки, повторная отправка с client_id идемпотентна. RLS отдаёт заявку только автору; публикация требует модератора с aal2. В опубликованном каталоге нет author_id, допуск животных остаётся unknown. Экспорт включает заявки; удаление профиля удаляет их по FK. Отдельная проверка: python3 scripts/verify_places.py — 18 локальных сценариев.

В demo новые места живут в памяти. В Supabase сохраняются собственные заявки и читаются опубликованные community-места. Порции списка — 40 записей из локального каталога; все OSM-маркеры карты сохраняются. Полноценная серверная пагинация большого каталога — следующий этап масштабирования.

Keychain/Keystore-сессии и PKCE разделены по origin Supabase, чтобы локальные токены не попадали в staging и наоборот. После этого обновления в backend-режиме потребуется заново войти; старый общий ключ не читается и не переносится. Изоляция проверена на синтетических токенах.


## Inline-отзывы мест

place_rating_stats (миграция 202610080008) вычисляет среднюю оценку/количество по всем отзывам опубликованных мест на сервере. Ограничение 50 отображаемых отзывов не участвует в агрегате; собственный отзыв запрашивается отдельно, чтобы форма не предлагала повторную публикацию. Экспорт включает place_reviews. Проверка python3 scripts/verify_place_reviews.py: 13 сценариев авторства, уникальности, агрегатов, скрытых мест, экспорта, удаления автора и отзыва JWT.

В demo оценки и отзывы меняются только в памяти. В backend отправка остаётся обычным insert под RLS и unique(place_id,author_id). PlaceDetailsSheet содержит форму внутри карточки, а PlaceRow и профиль подписаны на рейтинг. FullscreenMapArgs.focusPlace задаёт центр/масштаб без смены выбранного города. Начальная поставка для облака теперь включает 8 миграций; ранее подготовленный SQL Editor staging с 7 миграциями не обновлялся и не запускался в рамках UI-правок.

## Каталог городов — текущая версия

Встроенный каталог Минска сокращён до 130 парков/площадок. Нативный демо-клиент загружает другой выбранный город через системный geocoder и Overpass, используя публичный центр; повторные результаты хранятся в памяти. Backend вызывает city-catalog, где публичный центр определяется сервером. Локально применена миграция 009; в cloud она и функция ещё не развёрнуты. Для серверного запуска: supabase functions serve --no-verify-jwt (все функции); авторизация и отзыв JWT проверяются внутри функции. Не отключать проверку собственных getUser/catalog_actor.

Проверка python3 scripts/verify_city_catalog.py создаёт/удаляет только синтетические локальные аккаунты и служебный test-job: 12 сценариев прав, конкуренции, lease, кэша, скрытия OSM-кафе/ресторанов и отозванного JWT. В реальном локальном Edge запросе Гродно импортировано 9 парков; те же 9 мест загрузились в демо на iOS. Кэш не обещает наличие полного каталога каждого города: начальная область — 15 км вокруг центра, доступность зависит от публичных источников.

### Подтверждения допуска питомцев — миграция 018

`202610090018_pet_access_evidence.sql` применена только локально. Отдельная public-таблица содержит правила публичного места без person IDs: источник подтверждения (community/venue), конкретный режим (allowed/on_leash/forbidden), дату наблюдения, дату проверки, основание, условия и публичную ссылку. Venue-подтверждение требует HTTPS-ссылку. Обычный клиент не может записывать таблицу; публикация и отзыв идут через RPC с server-controlled moderator role и MFA. Скрытое место скрывает подтверждение; удаление места каскадное. Отозванный JWT не получает доступ через таблицу или city RPC.

Подтверждения входят в страницы `search_places`. `city_place_pet_access` учитывает и основной город места, и `city_catalog_places`, возвращает не больше 1000 записей.
