# Technical review and handover

The proposed acquisition is a product/source-code asset transfer. Asking price: USD 7,900, negotiable. Minimum price, exclusivity, support hours and payment arrangements have not been agreed.

## Proposed inventory

| Asset | Qualification |
| --- | --- |
| Flutter source and localization | Validate the exact accepted commit |
| Backend migrations, RPCs and functions | Deployment/acceptance are separate |
| Original design sources and review history | Per-screen approval/native rollout vary |
| Tests and utilities | Historical native targets may need updating |
| Setup, architecture and readiness guides | Some historical material is in Russian |
| Attributed fonts/geographic datasets | Preserve their licenses and notices |

Generated browser bundles and bulk archived check outputs are omitted from this branch. The owner's full working archive is retained separately. Agree additional evidence and the final inventory after inspection; repository access does not itself complete a rights transfer.

Credentials, private records, signing material and personal service/developer accounts are excluded. Domains, social accounts, trademark rights and store-listing transfers are not promised by repository access.

## Review sequence

1. Read the README, overview and readiness notes.
2. Run the demo and inspect feature modules/backend contracts.
3. Confirm included assets, transferable rights and third-party licenses.
4. Agree a scoped synthetic-data review environment with buyer-owned services.
5. Record launch work, accepted defects and any finite paid support.
6. Agree commercial and transfer terms before final delivery.

A guided walkthrough can precede broader code access. Production access and a whole local working-directory upload are not evaluation prerequisites.

## Delivery preparation

- Identify the accepted commit/tag and included/excluded files.
- Inspect the delivery tree **and Git history** for secrets/private data. Ignore rules and pattern scans are not a complete audit.
- Retain lockfiles, migration ordering, provenance and font notices.
- Use buyer-owned backend, map, mail, notification and distribution accounts; verify quotas/costs directly.
- Document variables without credentials and demonstrate clean setup.
- Validate flows and authorization in the target environment.
- Define support duration, hours, deliverables and completion criteria in writing.

No open-source license or redistribution permission for original assets is granted by this guide. Transferable rights require the owner's agreement; third-party licenses remain applicable.
